# Simplify the open ask card — UI atlas (illustrative only)

Atlas for [`../../specs/simplify-ask-card.md`](../../specs/simplify-ask-card.md): every view of the feature, its card (from the markdown) and one low-fi
frame per state, with the flow between views. **Illustrative only**: the mockups decide
anatomy, states and copy intent, not the final look. All names and data are fictional.

## Open it

Serve the directory that holds both the atlas and the specs so the card links resolve, e.g.:

```bash
python3 -m http.server 8899 --bind 127.0.0.1
```

The sidebar groups views by area; deep links: `#A3` (view), `#A3-s2` (state), `#overview`.

## Review

Comment in the PR by state id (`A3-s2`). The toolbar's **Comment** mode pins a thread to an
element of a frame; threads stay in your browser until **Export for repository** replaces
`comments.js`, which you then commit.

## Single source of truth

Text lives in the markdown, never in the generator: the UI map `simplify-ask-card-ui-map.md` (areas, view
list, mermaid flow) and one cards file per area (configured in `generate.mjs`). The mockup
modules own only fixtures, renderers and states. Generation fails when a mockup-stage view
has no states, states have no card, map and card disagree on a name, or a card lacks a field.

## Regenerate

```bash
node generate.mjs
```

Never edit `index.html` or `atlas.mjs` by hand. View and state ids are review anchors: append,
never renumber. `tokens.css` is generated by `node tokens.mjs` from the app's own tokens; prove it with the design-storyboard skill's `sync-tokens.mjs --verify`.
