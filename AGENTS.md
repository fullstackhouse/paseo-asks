# paseo-asks

Paseo plugin: agents record what they need from the human (asks) via MCP; Paseo lists them with action buttons; answers go back to the agent.

## Layout

- `index.server.ts` wires everything. `server/`: `store` (one JSON per workspace), `outbox` (disk-backed, steers messages into a running turn when the provider can, else holds them until the turn ends), `service` (MCP tools + human actions + agent instructions), `file-paths` (makes inline-code paths in ask bodies open from the workspace: a file only another worktree has gets its absolute path), `bridge` (stdio MCP script, written to the data dir at start), `listener` (localhost HTTP the bridge calls), `agents` (agentId → workspaceId), `discuss` (Discuss: an explainer agent in a new worktree workspace of the owner's repo; a read-only side chat in the ask's workspace when that fails. `discussionAgentId` links it: the asks tools look an ask up in the caller's workspace, except the one the caller discusses; `asks.list` for a workspace includes the ask it explains, and the explainer's own ask ids start after it), `archive-discussion` + `worktree` (the Archive explainer workspace button: refuses while anything there is going on or isn't the explainer's, lists uncommitted files for the human to confirm; archiving a workspace stops all its agents and terminals and force-removes the worktree), `gh` (every gh call; pauses on a spent rate limit), `github` + `deployments` + `watcher` (live PR state via `gh`, preview deployments via one `gh api graphql` call per PR, subscriptions), `last-output` (each agent's latest reply, seeds side chats).
- `client/` + `index.client.tsx`: React Native only (runs on mobile). Colors from `theme.colors`. Open URLs with `openExternalUrl` (default browser); `window.open` opens an unauthenticated in-app Paseo window. Render ask bodies with `Markdown` from `@getpaseo/plugin/client/ui`. Pass the original source; do not add a plugin parser or renderer.
- `shared/asks.ts`: Zod schemas and RPC contracts. The sidebar count (`waitingCount`) skips snoozed workspaces: `client/snoozed.ts` observes `paseo.workspaces` and `shared/snooze.ts` keeps the ids; hosts without snooze omit `snoozedAt`. `client/summary.ts` reports, for every workspace with any ask, its waiting count and waiting asks (`entries`, for the host's Overview) through the host's `addWorkspaceSummaryItem` (FSH hosts from fullstackhouse/paseo#83; typed locally) so entering a workspace can open the Asks panel. It treats snoozed workspaces like `waitingCount`: nothing waiting. `shared/settings.ts`: host-wide display settings, edited in `client/SettingsScreen.tsx`.
- `preview/`: own package.json; renders `client/` with react-native-web and mocked host modules for screenshots (`docs/*.png`). Not shipped. Markdown is shown as source there; verify diagrams and rich text in Paseo.

## Load-bearing facts (Paseo 0.12)

- Background workspaces (`workspace.background`, e.g. Inbox runs before the human opens them) get no asks: every tool call returns `BACKGROUND_SKIP` and stores nothing, and the unrecorded-ask nudge skips them. The tools stay, because an agent's tools are fixed at creation and the human may take the run over.
- The stdio bridge inherits `PASEO_AGENT_ID` from the agent process; that is how a tool call knows its caller. The HTTP MCP option cannot do this. Codex strips it on Paseo hosts before fullstackhouse/paseo#98, so the bridge also sends its cwd and `pickCaller` picks the running agent there, skipping providers that send their own ID (`COMPAT(codex-agent-id)`).
- `agents.ref(id).send()` interrupts a running turn unless `activeTurnBehavior: "steer"`. On a provider without steering (`capabilities.supportsSteering` unset) that steer still interrupts, so the outbox waits for idle there.
- `useWorkspace`/`useAgent` throw outside a workspace panel (e.g. the global Asks screen); resolve names on the server instead.
- Plugin server code cannot write settings, so clients poll (`POLL_MS`).
- Claude plan mode prompts even for `toolPolicy.preapproved` MCP tools; the server auto-allows `mcp__asks__*` via `agent.permission_requested`.
- Turn-end hooks carry no timeline. Read the turn with the host's `latestTurn` (`@getpaseo/plugin/server`, FSH hosts from `0bd77c5`; typed locally in `server/host-sdk.ts` until the npm SDK has it) before recording the reply or checking for an unrecorded ask.
- Nudge classifier = child agent via `agents.create` (owner's provider, cheapest model, `outputSchema`, `autoArchive`). Plan mode makes it explore and call AskUserQuestion; Claude fences the JSON in prose, so parse loosely.
- Scheduled runs: Paseo archives a run's workspace when it ends, which would hide its asks. `schedule.run.finish.before` (FSH hosts from fullstackhouse/paseo#106; typed locally in `server/host-sdk.ts`) flags runs whose agent left `open` asks, so Paseo keeps the workspace, and notifies once per run. Registration is in `try`: older hosts reject the hook name.
- `ask_create`/`ask_update` reject an ask that bundles several questions (`server/bundle.ts`), judged from the title and action labels only: bodies often list questions meant for someone else. The instruction alone didn't stop it, because skills told agents the opposite. Add a test case when you widen a pattern.
- The GitHub quota (5,000 GraphQL points/hour) is shared with every other `gh` user on the machine, the Inbox plugin and the daemon included. The watcher reads each PR once per pass and skips asks whose PR is merged (orphaned ones too: the human still acts on their cards) and asks in archived workspaces (out of the human's queue; the daemon's workspace list is read once per pass): agents leave merged PR asks open by the hundred, and polling them ran the quota out for everyone.
- Chat cards (`shared/timeline.ts`) see one tool call at a time and no reliable order, so the server stores `callKey()` of the agent's latest call as `lastCall`; the card whose own key matches is live, older ones render their snapshot from the call's input and result. Keep the tool result's text unchanged: cards parse it, and the e2e cassettes hash it.
- Plugin subprocess runs under Paseo's Electron helper: the bridge runs with `ELECTRON_RUN_AS_NODE=1`.

## Commands

- `npm run typecheck` (client and server tsconfigs), `npm test` (vitest).
- `npm run e2e`: real Paseo daemon (the FSH CLI bundle that `e2e/fsh-host.mjs` downloads by tag and sha256 before each run, since the plugin needs FSH-only host exports; `e2e/` pins Claude Code) in a temp `--home` and `HOME`, plugin installed, Haiku and Codex (`gpt-6-luna`, pinned `@openai/codex`) agents answered from `e2e/cassettes/` by a local proxy (`ANTHROPIC_BASE_URL`; Codex via a custom `model_provider` in the sandbox's `~/.codex/config.toml`). No network, runs in CI. `unprompted.e2e.ts` checks that agents create asks without being told to, on the first turn (the nudge would mask a miss). `E2E_PASEO_CHECKOUT=<built paseo checkout>` runs on a local host build instead of the pinned tag; the Codex scenario needs one until the pinned tag has the Codex alwaysLoad fix (TODO in `fsh-host.mjs`), and is skipped otherwise. After changing a scenario, a prompt, or anything the model sees (nudge text, tool output), re-record: `npm run e2e:record` with `OPENROUTER_API_KEY` in the env or `e2e/.env` (the proxy adds it; agents only see a dummy key), then commit the cassette. A replay miss fails the run and lists the unmatched request.
- Verify every change in a separate Paseo, never the main daemon (a reload swaps the plugin under running agents; never restart it). Setup is in the Paseo fork (`~/src/fsh/paseo`): `docs/development.md` "Test a change next to your main Paseo", `docs/plugins.md` "Test a plugin change". In short: from a Paseo checkout, `npm run dev:seed-home`, point `plugins.paseo-asks.path` in `.dev/paseo-home/config.json` at this worktree (link `node_modules` in), start `scripts/dev-daemon.sh` and `scripts/dev-app.sh` with a free `PASEO_LISTEN`/`EXPO_PORT`, `paseo run --home .dev/paseo-home --provider claude/claude-haiku-5-5 ...` to raise asks, then drive the web app with Playwright. Reload with `paseo plugin reload paseo-asks --home .dev/paseo-home` (`plugin ls` must say `running`).
- Act on an ask from a terminal: POST `/act` on the port in `~/.paseo/plugin-data/asks/server.json` with its bearer token.
